# AXIOM · 첫 제품화 범위와 현재 우선순위

갱신: 2026-09-28. **전체 목표와 현재 우선순위는 [통합플랫폼 내재화](internal-platform.md)가 기준이다.**
사용자는 Foxglove·FiftyOne·Applied Intuition·Foretellix에 대응하는 네 기능 영역의 내부 통합을 우선한다.
이 문서는 이미 구현한 첫 로컬 평가 모듈의 범위·운영 경계를 보존한다. 플랫폼 전체 목표를
이미지 평가판으로 축소하거나, 외부 OEM 구매/상용 출시를 내재화의 선행조건으로 삼지 않는다.
이전 CARLA 연구 문서의 '다음 작업'도 자동으로 최우선 작업이 되지 않는다.

## 첫 사용자와 제공할 업무

첫 사용자는 지원되는 로그·이미지와 모델 버전을 비교하는 센서/인지 검증 엔지니어다.
첫 배포 형태는 신뢰된 단일 운영자의 로컬/전용 설치형 평가판이다. 불특정 외부 사용자,
공유 SaaS, 다중 고객 격리 또는 인증/안전성 보증 제품으로 배포하지 않는다.

완결할 업무는 **지원 로그 등록 → 원본 이미지·라벨 개정 고정 → 모델 A/B 추론·평가 →
동일 조건 확인 → 실패 이미지 조사 → 전체 분모와 출처가 있는 검토 보고서 내보내기**다.
CARLA 주행 품질이 통과해야 이 업무를 사용할 수 있도록 의존시키지 않는다.

## 이번에 제품 경로로 연결한 것

내재화 I1의 [Investigation cases](cases.md)는 원본 로그 구간과 평가 이미지 근거를 같은 Case에
연결한다. 이 기능은 새 schema12를 사용하며 기존 평가판의 데이터 조사·평가 기능을 확장한다.
기존11-only 패키지 대신12를 지원하는 새 패키지를 사용하고 먼저 백업의 복원본으로 시험한다.

`Detection datasets → Compare evaluations`에서 저장된 두 평가를 비교한다.
같은 REST API를 화면과 SDK가 사용한다. Dataset manifest, split, class mapping,
평가 기준 및 runtime policy가 다르면 `not_comparable`, 입력 범위가 미완결이면
차이값을 보류한다. Model manifest/weights는 비교 변수로 허용한다.
비교 가능한 완전한 입력에서만 B−A와 이미지별 TP/FP/FN 차이를 제공한다.
필터로 화면을 줄여도 점수와 JSON/HTML export에는 전체 선택 이미지가 남는다.

새 기능은 원래 평가를 변경하거나 재추론하지 않는 읽기 기능이다. Export는 고정된
원본 manifest hash에 연결된 검토 요약이며, 이미지·모델 파일의 전체 백업이나
서버에 저장된 사람의 승인 기록은 아니다. 통계적 유의성이나 출시 승인을 자동 판정하지 않는다.

단일 호스트의 schema11/12 데이터는 `ade2e.workspace_backup`으로 cold backup/verify/restore한다.
원본 API/worker를 먼저 멈춰야 하며 도구가 임의로 프로세스를 종료하지 않는다.
복원은 새 디렉터리에만 가능하다. [운영 절차](workspace-backup.md).

| R&D | CARLA 저속 제동·LiDAR 관측 범위 | 기존 결과와 실패를 보존하고 **기본 개발 대기열에서 분리**한다. 고객 출시 약속을 직접 막을 때만 범위·종료 기준과 함께 재개한다. |

각 상태의 구현 여부와 검사 결과는 [제품화 인수 기록](product-pilot-acceptance-20260928.md)에 별도로 남긴다.

후속 배포 경로는 [로컬 평가판 패키지](local-pilot.md)를 따른다. 기존 개발 실행기는 유지한다.
로컬 패키지 인수 후에는 [내재화 단계 I1–I3](internal-platform.md)의 공통 Segment/Case,
평가·태그·coverage·재시험 연결을 우선한다. 승인된 내부 로그의 실제 업무 인수와
clean source/dependency 설치·접근 통제는 병행한다. 다중 사용자 SaaS나 모델 연구로
범위를 무심사 확장하지 않는다.

## 범위 밖

아래는 **이 로컬 평가 모듈의 초기 범위 밖**이며 전체 내재화 장기 목표에서 제외한다는 뜻은 아니다.
정밀 차량/센서 실측 보정, 모든 ODD, HIL 전체, neural reconstruction, 임의 영상/RAW/custom
schema, 학습형 주행 스택, 대규모 GPU 분산 실행은 첫 로컬 평가판의 필수 범위가 아니다.
현재 MCAP 128MiB/100,000-message, 평가 split 최대256-image와 지원 decoder 제한은 유지한다.
크기 제한을 제거하는 것을 대용량 인수로 취급하지 않는다.

## 다음 작업 선택 규칙

각 변경은 '누가 새로 무엇을 끝낼 수 있는가', '어떤 배포 차단 요소를 제거하는가',
'일반 제품 경로로 전달되는가'를 설명해야 한다. 주요 동시 작업은 사용자 업무 하나와
배포/운영 과제 하나로 제한한다. 모델 연구는 고객 요구와 관계없는 기술 완벽성을
이유로 이 작업들을 중단시키지 않는다. 보고의 첫 항목은 사용자 업무의 변화이며
시험 수·원본 hash 수는 그 뒤의 근거다.

성과는 첫 결과까지의 사용자 조작·시간, 개발자 도움 횟수, 설치/복원 성공, 수작업 감소로
확인한다. 기존의 '전체25%' 추정이나 특정 주행 점수를 출시 준비도 대신 사용하지 않는다.
