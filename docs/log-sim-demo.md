# Log Sim · 로그 조사에서 조건 변경과 비교까지

## 실도로 라이브러리 → 일괄 분석 → 우선순위 조사 → Case 묶음

Log Sim 기본 화면은 실도로 원본 장면 라이브러리다. 기존 `source`·`case`·`variant`
링크는 유지하며, 새 `batch`·`candidate` 링크는 저장된 일괄 분석과 후보 조사 화면을 복원한다.

1. 원본 전방 영상과 원본 데이터셋 설명으로 장면을 선택한다.
2. **장면 분석 준비**에서 독립 장면, 입력 구간, 표본 수와 예정 실행 수를 확인한다.
3. **사건 탐색 + A/B 실행**으로 구간마다 기존 durable 큐에 참조 제어기 두 개를 실행한다.
   A/B는 같은 입력·seed42·기준 속도8m/s·정지 여유2m를 사용하고 차간 시간만1.5→3초로 바꾼다.
4. 판단 차이 비율 → 가감속 반대 비율 → 최대 가속도 요청 차이 순서의 후보 목록을 조사한다.
   지표는 각 후보 구간의 표본만 계산한다. 하나의 입력 구간 실행을 여러 후보가 공유한다.
5. 후보를 열면 원본 RGB·객체 BEV·A/B 요청을 같은 시점에서 재생한다. 요청 차트로 시점을 이동한다.
6. 검토할 후보만 선택해 최대100개 Case 묶음으로 저장한다. 저장 목록에서 기존 Case 조사 화면으로 이동한다.

현재 원본은 nuScenes mini10개 장면, 총404키프레임이다. 381프레임을15개 연속 구간으로
보존했다. 14프레임은128객체 입력 규격 초과, 9프레임은 해당 시점 이전 CAN 부재로 제외했다.
고밀도 장면의 lineage1MiB 제한 때문에 일부 유효 구간을 나눴으며 독립 장면 수를 늘리지 않는다.
Log Sim 전용 선택 계약 `nuscenes-log-selection/1`은 구간당2–64프레임을 지원한다.
VAD 모델 입력의3–16프레임 제한과 객체128개 제한은 유지한다.

| API (`/api/v1/log-sim`) | 기능 |
| --- | --- |
| `GET /library`, `POST /library` | 프로젝트 라이브러리 조회 / 운영자만 검증된 원본 등록 |
| `POST /batches/preview`, `POST /batches` | 입력 고정 미리보기 / 일괄 실행 |
| `GET /batches`, `GET /batches/{id}` | 저장된 분석과 실행 진행·후보 목록 |
| `POST /batches/{id}/retry` | 부분 제출 복구 또는 실패 작업 명시 재실행 |
| `POST /batches/{id}/case-bundles` | 완료 보고서의 선택 후보만 Case로 저장 |
| `GET /case-bundles`, `GET /case-bundles/{id}` | 저장된 Case 묶음 조회 |

Presenter Engineer는 실행·저장, Viewer는 조회한다. 원본 수입·프로젝트 grant·라이브러리 등록은
운영자 경로이며 legacy Case/Collection/Campaign API를 프로젝트 토큰에 개방하지 않는다.
UI와 SDK는 동일 API를 사용한다. 미지원·실패·불확실 실행을 정상 비교로 집계하지 않는다.

`scripts/prepare_log_sim_library.py`는 기존 승인된 연구 데이터에서 원본 scene/sample/annotation/CAN/
카메라 행과 해시를 보존한다. 원본 사용 범위는 **격리된 비상업 연구**이며, 공개 배포나 상업 이용
승인을 뜻하지 않는다. 결과는 원본 GT 객체를 받은 기준 제어기의 open-loop 요청 비교이며,
새 학습 모델·센서 재구성·폐루프 주행·실차 안전 검증은 후속 범위다.

실행 및 브라우저 확인 근거는 [일괄 분석 확인 기록](validation/log-sim-batch-20261009.json)에 기록한다.

## 사건 검색 → 동일 로그 A/B → 반복 시험

2026-10-09 추가. Log Sim의 원본 조사 화면에서 다음 업무를 완료할 수 있다.

1. **자동 사건 검색**에서 저속·정지, 감속, 전방 근접 객체를 필터링한다. 원본 속도·위치로
   계산한 검토 후보이며 학습형 인지나 확정된 실패가 아니다. 검색 결과를 누르면 원본 시점과
   조사 구간이 선택되고, 규칙·근거 hash를 포함한 메모로 Case를 저장한다.
2. Case 저장 후 **A/B 입력 확인**에서 동일 원본 전체 표본 수와 Case 표본 수를 확인한다.
   균형/여유 거리/짧은 간격 프로필을 선택하고 **동일 로그 A/B 실행**을 누른다.
3. 기존 큐가 고정된 하나의 SceneSequence를 두 개의 ReplaySpec/Experiment로 실행한다.
   가속도·조향·목표 속도·판단의 차이를 전체 입력과 Case 구간으로 나눠 확인한다.
   차트의 표본 또는 **원본에서 보기**로 기록된 영상 시점에 돌아간다.
4. 감속 요청/목표 속도 한도를 정해 **반복 시험 저장** 후 **다시 실행**한다. 같은 고정 입력과
   제어기 설정을 새 작업 두 개로 실행하고 요청 한도 충족 여부와 저장 출력 재현 여부를 각각 표시한다.
   Case·비교·반복 시험은 프로젝트에 보존되며 새로고침 후에도 조회한다.

현재 제어기는 `geometric-headway/1`이며 **학습 모델은 아직 연결되지 않았다**. nuScenes의
원본 객체 주석과 ego 상태, 또는 CARLA의 기록된 GT를 사용한다. `open_loop` 요청은 차량에
적용하지 않으며 원본 영상과 ego 경로는 바뀌지 않는다. 결과는 모델 품질·안전 합격·검토자 승인으로
승격되지 않는다. 회귀 기준도 차량 감속 실측값이 아닌 **제어기 요청**의 진단 기준이다.

저속은 0.3m/s 이하가 0.5초 이상 지속된 구간이다. 감속은 약0.5초 간격의 기록 속도로 계산하며
0.2초 미만 차분은 제외해 20Hz 속도 흔들림을 줄인다. 전방 근접은 자차 방향 앞15m/좌우3m의
**객체 중심** 기준이고 차량 외곽 간격이나 충돌 예측이 아니다. 규칙 버전·설정·원본 sample ID/hash와
분모를 보존한다. 지원되지 않는 샘플·변조·불완전/불확실 실행은 비교나 회귀 통과로 처리하지 않는다.

API prefix `/api/v1/log-sim`:

| API | 역할 |
| --- | --- |
| `GET /sources/{id}/events` | 검색어·종류·시간·페이지 조건의 기록 규칙 후보 검색 |
| `GET /replay-profiles` | 지원 참조 제어기 설정과 open-loop 범위 |
| `POST /comparisons/preview`, `POST /comparisons` | Case·원본 pin 확인, 멱등한 두 실행 제출 |
| `GET /comparisons`, `GET /comparisons/{id}` | 보존 실행·전체 표본 요청 차이·근거 hash |
| `POST /comparisons/{id}/regressions` | 완료 비교와 사용자 요청 한도를 고정 |
| `GET /regressions`, `POST /regressions/{id}/runs` | 저장된 반복 시험 조회와 새 실행 |

UI와 Python SDK는 같은 API를 사용한다. 조회는 Viewer, 생성/실행은 Engineer이며
legacy Case 도메인의 권한은 그대로다. 목록은 최근20개 비교/시험을 보여준다. 원본 nuScenes의
연구 범위 및 상업 이용 미승인 상태를 유지한다. 다음 연결은 실제 학습 모델과 지원 입력 계약이다.

2026-10-09. 외부 발표자가 로컬 화면을 공유하는 3–5분 연구 데모다.
기존 CARLA 원본과 nuScenes 연구 데이터를 사용한다. 현재 변경 사항의 실제 실행·브라우저
확인 결과는 문서 아래의 확인 범위에 별도로 기록한다.

## 화면에서 진행하는 순서

시작 화면의 **Log Sim · 로그에서 비교까지** 또는 왼쪽 **Log Sim** 메뉴를 연다.

1. **도심 우회전 · 앞차 반응** 원본을 선택한다. 카메라와 객체를 같은 시간축으로 조사한다.
2. 앞차 정지·자차 대기·재출발 사건을 선택하고 **Case 저장**을 누른다.
3. 앞차 정지 시간을 원본 6초에서 2초로 바꾸고 **변경 내용 확인**을 누른다.
4. **CARLA로 변경안 실행**을 누른다. 기존 Experiment 큐에서 실제 실행한다.
5. 완료되면 **원본과 비교**에서 원본과 변경 결과를 같은 시간축으로 재생한다.
6. 실도로 소스를 선택해 원본 전방 영상·객체 주석·자차 상태를 조사하고 Case로 저장한다.

실행은 고정된 원본 시나리오의 시작부터 진행한다. 선택한 사건은 조사 구간이며,
중간 시점의 시뮬레이터 상태 복원을 뜻하지 않는다. 조건 변경은 앞차의 정지 시간만 지원한다.
기존 지도·자차 제어기·seed·카메라 설정은 유지한다.

## 표시와 데이터의 범위

- CARLA 원본은 실제 엔진이 렌더링하고 보존한 RGB다. 기본 추적 카메라와 전방 카메라를
  전환할 수 있다. BEV/3D는 기록된 객체 위치를 보여주는 분석 화면이다.
- 저장된 실행 결과와 새 실행 상태를 구분한다. 엔진이 연결되지 않으면 새 실행 오류를
  표시하며, 저장 결과를 새로 계산한 것처럼 돌려주지 않는다.
- 원본 실행 → 기록 → Segment/Case → 변경 조건 → 새 실행의 식별자와 해시를 연결한다.
- nuScenes 객체는 원본 데이터셋의 주석이다. 새 탐지 모델의 출력이 아니다. 기존 연구용
  데이터에서 선택한 연속 구간만 사용하고 원본 영상의 시각과 프레임을 보존한다.
- 실도로 소스는 조사와 Case 저장을 지원한다. 실도로 장면을 CARLA로 자동 복원하거나
  촬영 영상을 변경된 경로의 센서 입력으로 사용하는 기능은 포함하지 않는다.

이번 실도로 입력은 `scene-0061`의 연속 **10개 키프레임·4.499초**, 전방 원본 JPEG 10장이다.
프레임마다 원본 객체 78–127개를 모두 보존한다. 다음 프레임부터 기존 128객체 계약을
넘으므로 구간을 여기서 제한했으며, 객체를 버리거나 최대 개수를 확대하지 않았다.
원본 행과 해시는 무손실 압축 lineage로 보존하고, MCAP는 약 2.1MB다.
자차 크기는 원본 실측값이 없는 명시적 참조 footprint이며, 데이터셋 객체 주석과 구분한다.

## 발표 환경

기존 Object Sim 전용 작업공간과 같은 로컬 서비스를 재사용한다.

```text
http://127.0.0.1:8033/#log-sim?project=project_bc937f94c7c94a7884993c074213a86c
```

인증은 기존 `.runtime/object-demo-20261009/access/presenter-token`의 프로젝트 토큰을
Workspace 설정에 입력한다. 토큰은 발표 자료에 포함하지 않는다. 새 외부 링크는 필요 없다.

시작·정상 종료·UI build 갱신은 [기존 전용 런처 절차](object-sim-demo.md#준비시작복구)를
따른다. 기존 서비스를 동시에 중복 시작하거나 다른 workspace를 종료하지 않는다.
원본 RGB를 복사하지 않고 기존 아티팩트를 참조하며, 실도로 입력은 선택 구간만 등록한다.

## API 연결

UI와 Python SDK는 같은 `/api/v1/log-sim` 계약을 사용한다. 새 실행 엔진이나 DB 테이블은
추가하지 않는다. 기존 버전형 카탈로그에 소스·Case 연결·변경 실행을 보존한다.

| 경로 | 기능 |
| --- | --- |
| `GET /sources?project_id=…` | 준비된 CARLA/실도로 소스와 지원 기능 |
| `GET /sources/{id}?project_id=…` | 기록된 사건·지표와 원본 재생 자료 |
| `POST /sources/{id}/cases` | 프로젝트 소스의 정확한 시간 구간을 기존 Segment/Case로 저장 |
| `GET /sources/{id}/cases/{case_id}?project_id=…` | 해당 프로젝트·소스에 연결된 Case 조회 |
| `POST /variants/preview` | 앞차 정지 시간 변경과 원본·Case 개정 고정, 아직 실행하지 않음 |
| `POST /variants` | 미리보기 hash 확인 후 기존 ScenarioV2·Experiment 큐로 실제 제출 |
| `GET /variants?project_id=…&source_id=…` | 보존된 변경 실행과 원본·Case 연결 조회 |

Case 저장과 실행 제출은 프로젝트 Engineer 이상 권한과 `Idempotency-Key`가 필요하다.
같은 요청의 재시도는 같은 키를 사용한다. Case의 프로젝트 접근은 선택한 Log Sim 소스에
연결된 범위만 허용하며, 기존 전역 Case API의 권한을 확대하지 않는다.
실행 상태·원본 아티팩트는 기존 Experiment API에서 조회한다.

변경 요청은 `project_id`, `source_id`, `case_id`, `case_revision`, `lead_wait_s`를 사용한다.
제출에는 미리보기의 `preview_hash`를 추가한다. 원본이나 Case 개정이 바뀌면 다시 미리보기한다.
CARLA 조건 변경 비교는 각각 `single` 실행이며 동일 입력 모델 A/B로 분류하지 않는다.

## 확인 범위

프로젝트 Engineer로 정상 화면에서 Case 저장 → 2초 미리보기 → 실제 실행 → 동기 A/B 비교를
완료했다. 원본·비교·실도로 재생, 비교 URL 새로고침, 실도로 Case 저장을 확인했고 브라우저
오류는 없었다. 첫 프레임 이전의 0초에서 멈추던 진입 동작과 RGB가 잘리던 배치도 수정했다.

| 관측 지표 | 원본 · 앞차 6초 정지 | 변경 · 앞차 2초 정지 |
| --- | --- | --- |
| 자차 목적지 도달 관측 | 21.45초 | 17.45초 |
| 자차 누적 정지 시간 | 3.8초 | 0.6초 |
| 최소 선행 간격 | 3.951m | 4.630m |
| 기록된 native 접촉 | 0건 | 0건 |
