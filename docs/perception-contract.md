# Perception experiments · implementation contract

This module is being implemented. Acceptance evidence belongs in status.md after actual API/worker/browser checks. Inference is a model prediction over a recorded image; it is not ground truth, calibrated probability, perception accuracy or a closed-loop driving result.

All paths below use `/api/v1/perception`. Existing `/api/v1/jobs` remains the simulation view of one shared durable execution queue; perception has its own typed public view. A perception job never creates a placeholder driving Scenario or Run.

## Model authoring

- `POST /model-artifacts?name=FILE_NAME`, body `application/octet-stream`: bounded 128 MiB original ONNX bytes, streamed to managed storage. Registration only stores bytes; it does not execute or certify compatibility. Return 201/200 `ModelArtifact{id,name,sha256,size_bytes,created_at,download_url}`. Repeated identical bytes/name resolve to one artifact. `GET /model-artifacts/{id}/download` verifies size/hash. No server URL fetch.
- `POST /models`: `ModelCreate{name,description,artifact_id,profile,input_width,input_height,labels,source,source_revision,weights_license,weights_license_url,code_license,training_data_note,note}`. `description` defaults empty; provenance fields use explicit unknown/empty where unavailable; name/note nonempty. Width/height 32..1280; labels 1..256 unique nonempty strings. The ordered label map is part of the manifest. Return immutable `ModelDetail` with these fields plus `id,revision,created_at,artifact:ModelArtifact,label_map_hash,manifest_hash,manifest_size_bytes,download_url`. Source/license fields are declarations, not legal approval. Model weight bytes and model definition have separate hashes.
- `GET /models` returns heads, `GET /models/{id}?revision=N` a selected revision (omission is the authoring head); `GET /models/{id}/revisions` newest first; `POST /models/{id}/revisions` is complete ModelCreate + `expected_revision`; `GET /models/{id}/export?revision=N` exact canonical manifest bytes. No overwrite of old definitions/artifacts.
- `GET /runtimes` returns `RuntimeMetadata{id,name,version,status,profiles,limits,limitations}`. Root optional adapter is `onnx-cpu`, version `0.1.0`. It supports `opencv_yolox_rgb_v1` and `boxes_xyxy_v1`. Runtime availability and model compatibility are distinct from registration.

`opencv_yolox_rgb_v1` is explicitly RGB raw 0..255 float32 NCHW, linear resize preserving aspect ratio, top-left padding 114, strides 8/16/32 grid decode, objectness × winning class score, class-aware continuous-coordinate IoU NMS, inverse resize to decoded image and clipped pixel xyxy. It targets the pinned OpenCV Zoo YOLOX-S distribution, not arbitrary YOLOX exports. `boxes_xyxy_v1` is RGB float32 NCHW divided by 255, stretch-resize, one float output `[1,N,6]` with model-input-pixel xyxy/score/zero-based class ID; class-aware NMS and inverse scaling. It supports a real input-dependent authored ONNX contract fixture and compatible user models. Neither profile is a general auto-detection mechanism.

## Submission and stored results

`POST /jobs` requires endpoint-scoped `Idempotency-Key` and body:

```json
{"label":"Review a recorded image","model_id":"model_...","model_revision":1,"runtime_id":"onnx-cpu","recording_id":"rec_...","channel_id":1,"ordinals":[0,2],"decoder_id":"ros2-cdr","decoder_version":"1","seed":42,"score_threshold":0.35,"iou_threshold":0.45,"max_detections":100}
```

Ordinals are explicit unique file ordinals, 1..64 frames, retained in supplied order. Thresholds are 0..1 and max detections 1..300. Submission pins model/weight/label-map manifest, runtime and decoder versions, recording SHA and channel/schema identity, original message SHA/size and log/publish timestamps for each selected ordinal. Every input must belong to the declared recording/channel and supported camera decoder. No implicit current frame or latest model. Model inference is never performed in the API request.

`GET /jobs?limit=100&before_seq=N&status=...` returns `{items:PerceptionJobSummary[],next_before_seq}`; `GET /jobs/{id}` returns `PerceptionJobDetail`; `POST /jobs/{id}/cancel` requests cancellation. Same lifecycle statuses as the common queue. Existing simulation APIs reject perception IDs rather than pretending they are driving evidence.

`PerceptionJobSummary{id,submission_seq,label,model_id,model_revision,model_name,runtime_id,runtime_version,status,created_at,updated_at,started_at,dispatched_at,finished_at,error,input_hash,worker_id,lease_expires_at,cancel_requested_at,cancellation_supported,outcome_uncertain,counts}`. `counts{total,running,completed,failed,not_attempted}` always uses the fixed full input denominator. `PerceptionJobDetail` additionally carries `request,model_snapshot,recording_snapshot,inputs,frames,events,events_total,manifest_hash,manifest_size_bytes,download_url` (manifest metadata null until terminal). Inputs carry `selection_index,recording_id,recording_sha256,channel_id,ordinal,log_time_ns,publish_time_ns,message_sha256,message_size_bytes,decoder_id,decoder_version`.

Each frame result is `{selection_index,status:not_attempted|running|completed|failed,error,input:input_descriptor,image:null|{sha256,size_bytes,width,height,download_url,capture_time_ns,frame_id},detections:[],runtime:null|runtime_evidence,output_hash,created_at,started_at}`. A failed frame is distinct from completed with zero detections. Every completed frame saves the exact decoded input PNG and validated predictions under the live claim, then commits independently. The frame enters `running` with a committed `started_at` before decode/inference. Cancellation or interruption retains committed results and converts an in-flight frame without a published prediction to `failed` with an explicit reason; `not_attempted` means genuinely unstarted. Terminal counts always have `running=0`. Output images/downloads verify size/hash. Native inference cancellation is acknowledged only after its child process has stopped. No automatic resubmission after uncertain ownership.

Detection contract: `{id,class_id,label,score,bbox_xyxy:[x1,y1,x2,y2]}`; finite bounds within decoded-image width/height, positive area, labels exactly match pinned class map. `score` is a model score, not a calibrated probability. Runtime evidence includes runtime ID/version, actual engine/provider/version, model SHA, profile/pre/postprocessing versions, tensor SHA/shape, inverse resize parameters, clipping/NMS counts and observed durations. Core independently validates all plugin output identities and values before publication.

`GET /jobs/{id}/export` returns terminal canonical evidence for completed, failed, cancelled or interrupted jobs, preserving the full input denominator and partial results. Input/output content hashes are distinct from timing metadata. PNG URLs always refer to saved input copies associated with that exact job/frame.

## Saved comparison

`POST /comparisons` with `{name,note,left_job_id,right_job_id}` and stable endpoint-scoped `Idempotency-Key` captures two terminal job manifests. `GET /comparisons` lists summaries; `GET /comparisons/{id}` returns the stored comparison; `GET /comparisons/{id}/export` returns exact bytes. It must preserve prior comparison bytes after model revisions or new jobs.

`ComparisonDetail{id,name,note,created_at,left_job_id,right_job_id,left_manifest_hash,right_manifest_hash,policy_version,configuration_differences,rows,counts,manifest_hash,manifest_size_bytes,download_url}`. Row keys use recording SHA/channel/ordinal plus original message SHA; actual decoded PNG SHA must also match before a same-input prediction comparison. `row{key,status:same_input|input_changed|left_only|right_only|not_evaluated,left:frame|null,right:frame|null,detection_count_delta:null|integer,predictions_identical:null|boolean}`. Different model/threshold/label map/configuration is disclosed, not called accuracy improvement/regression. No invented bbox matching, ground truth, precision/recall or safety verdict. Counts are `{total,same_input,input_changed,left_only,right_only,not_evaluated}` and preserve all union inputs and failures. `configuration_differences` is `[{field,left,right}]`; comparison lists return `ComparisonSummary[]`. The immutable comparison export is an envelope `{schema_version,comparison,left,right}` embedding both captured terminal job details, so its SHA refers to the complete source evidence as well as the report. Prediction-content hashes exclude observed durations and timestamps; separate stored payload hashes and terminal manifest hashes protect those metadata too.

## Extension and storage boundaries

Schema 6 migrates the common queue to a kind discriminator and nullable simulation-only subject columns. Existing simulation IDs/sequence/events/resources/campaign references and all old business rows must be preserved and foreign_key_check must pass. Worker lifecycle/ownership stays common; preparation, typed result publication and public inspectors are domain-specific.

Engine imports and model graph parsing live in an optional adapter package. ONNX external data, custom operator domains, unknown graph signatures and unsupported output layouts fail closed. Bounded subprocess timeouts protect worker responsiveness; this is not an OS security sandbox or a product-wide memory limit. Model registration is for locally trusted model files; multi-tenant model execution requires a separate isolation/release gate.
