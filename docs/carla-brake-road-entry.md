# CARLA 고정 위치 진입과 제동 분기

2026-09-14 · `carla-brake-protocol/3`의 첫 실제 commissioning은 준비 단계에서 실패했습니다.
제동 계측은 시작하지 않았습니다. 기존 protocol1/2의 원본과 판정은
유지하며, 새 조건을 과거 실패 시험의 재현이나 제동 개선으로 취급하지 않습니다.
플랫폼 job/API에 연결된 기능이 아닌 선택형 native 개발자 진단입니다.

## 바꾸는 이유

이전 throttle 준비는 마지막5개 표본이1.9–2.1m/s 범위 안에서도 계속 감속했습니다.
속도 범위와 |종방향 가속도|≤0.1m/s²를 동시에 만족한 준비 표본은 없었습니다.
계측 시작 위치도 velocity injection보다 약1.142824m 앞이었습니다.
또한0.25초 coast 후에는 pulse 진입 창을 벗어났습니다.
[이전 실제 근거](validation/carla-brake-initialization-2026-09-14.json).

새 비교에서는 같은 throttle 준비를 사용하고, 동일하게 선언한 도로 평면의 첫 통과
관측에서 즉시 분기합니다. 한 번의 engine 상태를 복제했다고 가정하지 않으며, 매번 새
ego로 준비한 원본 이력과 실제 진입 상태를 별도로 비교합니다.

## 실행 전에 고정하는 조건

| 항목 | Protocol3 |
| --- | --- |
| 엔진·환경 | 기존 CARLA build1ae5356·adapter0.8·Town10HD_Opt, 같은 spawn·weather·physics readback |
| 준비 경로 | throttle만 사용; target velocity 주입 없음, 기존 자동 forward 요청 유지 |
| 준비 제어 | PI Kp0.08·Ki0.05, throttle0–0.35, 변화율0.1/s |
| 적분 | 실제 source dt; cached gear≤0에서 동결, 출력·변화율 제한 방향으로 포화될 때 anti-windup |
| 첫 명령 | 경과 시간을 적분하지 않음; slew에는 선언한 첫0.05초 명령 구간 사용 |
| 제한 | 기존 최대300 preparation tick·총30m·XYZ speed3m/s·횡방향1m·heading5° 유지 |
| 관측 창 | 연속21 snapshot·20 physics 구간, 약1초 |
| 운동 조건 | 모든 속도1.95–2.05m/s, 각구간 절댓값 Δv/Δt≤0.1, 각끝 snapshot 절댓값 a∥≤0.1m/s² |
| 자세·제어 | vz 절댓값≤0.01m/s·angular norm≤1°/s, 같은 양수 cached gear, cached throttle 범위≤0.002 |
| Raw 회전 상태 | 동일 frame의 유효 RPM과4 wheel omega, 각 상대 범위≤2%; 양수 RPM·omega 부호 유지·중앙값 절댓값>1e−6 |
| 진입 위치 | 요청 spawn에서 그 heading 방향으로12m인 평면의 최초 통과 snapshot; overshoot≤0.11m |
| 최초 통과 실패 | 관측 창 미충족·raw 상태 미평가·overshoot이면 계측 없이 실패; 재진입·보정·연장 없음 |
| 계측 분기 | 진입 F0 직후 throttle0과 지정 brake를 동시에 요청; 추가 coast tick 없음 |
| Pulse | command0–4에서 지정 brake, command5–79에서 brake0; 총80명령·81관측 |
| Coast | 80개 명령 모두 throttle/brake0; 원래 pulse level0도 같은 입력으로 별도 명시 가능 |

PI 상수와 위 한계는 **미보정 실험 조건**입니다. 관측 창 통과는 선언한 원본 필드의
안정성을 뜻하며 완전한 물리 정상상태·힘·클러치·접촉 또는 실제 차량 calibration의
증명이 아닙니다. RPM/omega의 상대 변화는 raw API 수치만 비교하며 단위를 확정하지
않습니다. 누락·잘못된 frame·0분모·부호 변화는 통과로 채우지 않습니다.

F0에는 마지막 준비 throttle와 그 구간의 가속도가 남습니다. 첫 pulse 응답은 F1,
첫 release 응답은 F6입니다. 첫 계측 Δv/Δt는 unknown이며 준비 응답을 삭제하거나
첫 coast/brake 명령의 결과로 재배치하지 않습니다.

## 비교 자격과 결과 의미

먼저 commissioning coast로 위 준비 조건이 실제로 가능한지 확인합니다.
Recipe를 바꾸면 새 버전·intent·source hash를 고정하고 실패 원본을 남깁니다.
그 뒤 선택한 동일 준비 방식에서 `[0,0.025,0.05,0.1,0.2,0.35,0.6,1]`의8개 level을
각1회 조사합니다. 과거 protocol2 coast를 새 기준 결과로 재사용하지 않습니다.

수집 완료와 pair 비교 자격은 별개입니다. 같은 version·seed·map·spawn·weather·physics와
준비 조건, 동일한 준비 명령 수·대응하는 제어 이력을 요구합니다. 실제 진입 위치 차이는
15mm, 속도 벡터 차이는0.005m/s, 회전 차이는0.05°, cached throttle 차이는0.0005 이내이고
cached gear가 같아야 합니다. 추가 종방향 가속도 차이0.02m/s²·angular velocity 차이0.05°/s·
raw RPM/omega 상대 차이2%도 선언합니다. 비교 실패는 `not_comparable`로 보존합니다.
20Hz·2m/s에서는 snapshot 간 약100mm 이동하므로, 평면 통과 성공이15mm pair 일치를
보장하지 않습니다. 위치 보정·시간 보간·좋은 반복만 선택하는 재시도는 하지 않습니다.

비교 가능한 동일 index에서 추가 속도 손실은 다음 기술량으로 표시합니다.

```text
L_b(k) = [v_b(0) - v_b(k)] - [v_0(0) - v_0(k)]
```

이는 같은 선언 조건에서 관측한 분기 후 응답 차이입니다. 다른 속도·이력·도로에 대한
brake gain이나 제동력 곡선으로 일반화하지 않습니다. 정지·release·미정지의 전체 분모를
유지하며 별도 속도·pulse 길이·sequence의 신규 holdout 없이 production 제어기 상수를
교체하지 않습니다.

## 당시 후속 가설과 이후 입력 분리 실행

아래 제안은 이후 별도 [입력 분리 계약](carla-throttle-isolation.md)으로 구현해 실제 두
분기를 실행했습니다. 고정 throttle에서도 가속도 교대가 남았으며, 이 문서의 protocol3
준비 실패와 계측 0건은 바꾸지 않습니다. 아래는 그 실험을 설계한 당시의 경계입니다.

동일한 준비 명령 이력과 실제 전환 상태를 비교한 뒤, 짧은 별도 진단에서 현재 PI를
유지하는 조건과 마지막 throttle을 고정하는 조건을 나눕니다. 기존 protocol3의 준비
실패를 통과로 바꾸는 시험이 아니므로 새 입력·소스·진단 계약을 먼저 작성해야 합니다.
Braking은 0으로 유지하고 공간·속도·소유권 중단 조건을 보존합니다.

고정 입력에서도 교대가 남으면 PI 명령의 교대만이 필수 원인이라는 가설을 반박할 수
있지만, 접촉·타이어·solver 중 원인을 확정할 수는 없습니다. 고정 입력에서 사라져도
feedback의 관여를 조사할 근거일 뿐입니다. 이후 같은 open-loop 입력에서 physics
substep만 바꾸는 별도 비교가 필요할 수 있습니다. 현재 원본에는 그 결과가 없습니다.
