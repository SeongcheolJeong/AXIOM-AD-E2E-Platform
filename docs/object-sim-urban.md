# Object Sim · 도심 주행 데모

2026-10-09. 기존 빠른 시작에 네 번째 **도심 주행** 프리셋(`urban_city`)을 추가했다.
설치된 CARLA `Town10HD_Opt`의 도시 배경을 원본 RGB로 보여주고, 같은 시각의 객체·경로·판단은
좌표 기반 3D로 조사한다. 기존 회피·양보·8대 교차로와 저장 결과는 유지한다.

**현재 상태:** UI/API/SDK와 도시 지도 작성 경로를 구현하고 **새 native A/B 2회 완료·원본 RGB
960장·누락 0**을 보존했다. 두 실행의 기존 기준은 통과했고 A를 프리셋의 저장 결과로 연결했다.
8033 전용 데모에 적용하고 브라우저 7개 업무·실제 API 미리보기 20개 조건을 확인했다.
작성한 대기를 교통 양보로 설명하던 자동 시연 문구를 수정하고 재기동한 API에서 원본 연결을 다시 확인했다.
첫 6초 probe `job_168e4c2647a146ad9c8a732dc1ce776a`의 지도 로딩 50초 timeout과
`outcome_uncertain:true`는 별도 실패로 유지한다.

## RGB 전환 깜빡임 수정

다음 원본을 확인하는 동안 canvas를 숨기던 동작을 수정했다. 같은 실행·센서·영상 격자에서는
직전 검증 영상을 계속 표시하고 새 원본이 준비되면 교체한다. 이때 `이전 검증 프레임 유지`를
표시하며 시각·원본 hash·다운로드 대상도 실제 보이는 프레임과 일치한다. 공통 재생의 준비 신호는
현재 요청에 맞는 새 원본을 표시한 뒤에만 true가 된다. 늦게 끝난 이전 요청은 현재 화면을 덮어쓰지 않는다.

무결성 오류는 영상을 숨기고 오류를 표시한다. 실행·센서·영상 격자가 바뀌면 이전 출처의 영상을
숨기고 새 원본을 기다린다. 프레임을 보간하거나 새로운 영상/차량 자세를 만들지 않는다.
실제 `CarlaCameraFrame`에 작성한 in-memory BGRA와 지연 응답을 연결한 브라우저17단계에서
픽셀·caption·출처, 대기·교체·늦은 응답·오류·출처/크기 전환을 확인했다.
`.runtime/object-urban-20261009/camera-display-fixture.json`은 이 UI 회귀 시험의 근거이며
native 관측 자료가 아니다.

8033의 현재 사용자 탭을 새 빌드로 새로고침하고 기존 도시 전방 RGB를5초 수동 재생했다.
DOM838개 표본에서 서로 다른 표시 프레임50개, 숨김0, 표시 frame ID·라벨·caption의 불일치0을
확인했다.355개 표본은 다음 원본 준비 중 이전 검증 영상을 유지하는 상태였다. 수집 receipt의
5.521초에는 일시정지 뒤 표본도 포함된다. native canvas 픽셀을 다시 읽어 비교한 시험은 아니며,
픽셀·출처 대응 회귀는 위의 작성 fixture로 별도 확인했다.

이번 수정의 scoped40개(ZIP29·배치2·Story6·재생시계3)와 production build를 확인했다.
`.runtime/object-urban-20261009/camera-display-native.json`과 `camera-display-restart.json`에
표시 표본과 적용 빌드를 보존했다. 모든 기기/브라우저의 무깜빡임이나 센서 FPS 증가를 뜻하지 않는다.
새 native 실행·원본 변경은 없다. [소스·표시 회귀 근거](validation/object-rgb-display-20261009.json).

## 일반 화면에서 사용

1. [전용 Object Sim](http://127.0.0.1:8033/#object-sim?project=project_bc937f94c7c94a7884993c074213a86c)의
   **빠른 시작 → 도심 주행**을 선택한다. `장면 준비 필요`는 해당 프로젝트의 명시적 지도/시나리오
   연결이 없다는 뜻이다. `편집 준비됨`도 실행 성공을 뜻하지 않는다.
2. **시연 시작**으로 연결된 A 원본을 연다. 기본 `자동` 배치는 검증된 scene의
   CARLA Town native 지도 정보를 보고 카메라 중심으로 전환한다. 프리셋 이름만으로 판단하지 않는다.
3. **전방 / 추적**과 **카메라 중심 / 분석 중심**을 바꾸며 같은 보존 시각을 조사한다.
   카메라 중심은 원본 RGB 약 65%, 좌표 기반 분석 장면 약 35%를 사용한다.
   지도 배경이 없는 절차적 도로 결과의 자동 배치는 기존 분석 중심을 유지한다.
4. **직접 수정하기**에서 자차 목표 속도를 바꾸고 일반 저장·실행 경로로 B를 만든다.
   완료 후 기준 A와 같은 시간축에서 비교한다. 설정/지도/seed 등 호환 조건과 원래 판정을 유지한다.

저장된 원본 없이 시연용 영상을 생성하거나 이전 실행을 새 실행 결과로 표시하지 않는다.
자동 설명 구간은 실제 보존 planner 사건이 있어야 구성되며 수동 조사에서는 원본 전체 시간을 탐색한다.

## 현재 작성 프로필

아래는 실행에 제출하는 설정이며, 관측 결과나 통과 수치가 아니다.

| 항목 | 고정 입력 |
| --- | --- |
| 지도 | 설치된 `Town10HD_Opt` native 카탈로그 개정·OpenDRIVE hash |
| 차량 | 자차 1대와 반대 차로 진행 차량 2대, 모두 기존 GT 기반 reactive planner |
| 행동 | 자차 명령 시각 3초부터 2초 대기 후 목적지 주행·정지 |
| A/B | 자차 목표 속도 A 4 m/s, B 6 m/s; 반대 차로 두 차량은 3 m/s |
| 길이·표본 | 본 실행 24초, physics 20 Hz, seed 42; 구도 probe는 별도 6초 |
| RGB | 자차 전방·외부 추적 각 960×540, 각 10 Hz, 기존 BGRA8 원본 보존 |
| 관측 해석 | 작성한 대기와 실제 planner 판단을 구분하며, 대기를 교통 안전 반응으로 설명하지 않음 |

[준비·실행 스크립트](../scripts/object_sim_urban_demo.py)는 과거 Town10 직선 경로를
현재 등록 native 그래프에 다시 맞추고, 반대 차로 경로의 각 연결도 확인한다.
새 실행·불변 시나리오 참조·지도 hash·프리셋 연결은
`.runtime/object-urban-20261009/filming.json`에 보존한다. 과거 Town10 주행 성공은 새 planner·
카메라 설정의 통과로 승격하지 않는다.

첫 실패 후 이전 소유 프로세스·그룹·dispatcher의 부재와 2100 포트 닫힘을 확인했다.
기존 서버 로그는 `Killed`로 끝났지만 OOM 등 정확한 원인은 확정하지 않았다.
같은 전용 소유 환경만 재시작하고 Town10 준비·동적 actor 부재를 확인한 뒤, 일치하는 격리 기록만
잠금 아래 해제하여 리소스를 reconcile했다. 다른 엔진은 종료하지 않았으며 원래 실패를 성공으로
재분류하지 않았다. 근거는 `.runtime/object-urban-20261009/{probe,recovery-remote,reconciliation}.json`이다.

이번 변경의 scoped backend/adapter/script 91개(43+40+8), frontend 20개, SDK 13개와
production build를 확인했다. 전체 저장소 시험 통과라는 뜻은 아니다.

실제 브라우저에서 네 번째 프리셋 진입, native Town 자동 배치, 960×540 원본과 hash,
A/B 공통 시간, 전방/추적 전환, 분석/카메라/자동 배치 전환, 수동 조작에 따른 자동 시연 중단과
짧은 수동 재생을 확인했다. 1920×1080에서 RGB와 분석 장면이 함께 보였고 브라우저 오류와
새 실행 제출은 없었다. 근거는 `.runtime/object-urban-20261009/browser-acceptance.json`이다.
실제 API 미리보기는 자차 목표 속도만 4→6 m/s로 변경하고 지도·카메라·행동·평가 기준·기존 binding을
보존했다. 20개 확인 조건은 `api-preview-acceptance.json`에 기록했다. 미리보기는 실행하지 않았다.

후속 내용 검토에서 작성한 `brief_wait`를 양보/간격 반응으로 설명하는 문구 오류를 발견하여
`object-story-rules/3`에서 실제 판단 이유에 맞게 고쳤다. 재기동한 API는 **설정한 대기**와
시나리오 `wait` 명령이라는 설명을 반환했다. 첫 설명의 보존 응답 시각 3.05초와 양쪽 원본
manifest를 유지했다. 대기·도착 두 구간의 A/B 시연 구성은 설명 정지 포함 16초다.
`.runtime/object-urban-20261009/story-label-acceptance.json`에 API 확인을 기록했다.

Apple M4·Chrome 155·1920×1080에서 카메라 중심의 전방 A/B를 첫 원본 준비 후 한 번 측정했다.

## API·표현 경계

기존 `object-sim-presets/1`·`object-sim-preview/1`에 `urban_city`를 추가한다.
미리보기는 `ego_speed_mps`만 간단 설정으로 받으며 일반 객체 드래그도 기존 제약을 따른다.
binding은 절차적 생성 표시가 없는 CARLA Town native 지도 출처를 요구한다.
실제 실행에서는 설치된 지도의 OpenDRIVE hash를 고정 개정과 다시 비교한다.
저장·실행·Story·A/B API와 Python SDK의 사용법은 [빠른 데모](object-sim-demo.md)와
[관측 사건 시연](object-sim-story.md)을 따른다.

건물·가로수·도시 표면은 설치된 CARLA 환경에서 렌더된 RGB에만 나온다. 웹 3D는 보존된
차로·신호·객체 위치를 표현하며 native 건물 mesh를 복제하지 않는다. CC0 차량 외형도 설명용이다.
카메라 해상도·보존 주기, physics 표본 주기, 웹 렌더 FPS는 서로 다르며 중간 차량 자세나 영상을
만들어 원본처럼 제시하지 않는다. 다른 기기·원격 연결·더 큰 해상도의 재생 성능은 별도 확인 대상이다.

이 데모의 planner 입력은 지도·객체 GT이며 RGB 인지 정책이 아니다. CARLA 콘텐츠의 개별
재배포 권리는 별도 검토 대상이며 engine mesh/texture를 웹 자산으로 배포하지 않는다.
실차 안전성·물리 센서 정합·도시 전체 주행 인수·상용 출시 완료는 이 범위에 포함하지 않는다.
